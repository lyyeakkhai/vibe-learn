# Implementation Prompt: 4.7 - Environment Variable Validation with Zod (Backend & Frontend)

## 1. Goal
Implement robust, type-safe environment variable validation using **Zod** across both the **frontend** (Vite + React) and **backend** (NestJS + Node.js). Ensure that missing, invalid, or malformed configuration values are caught immediately on startup with clear, actionable diagnostics, preventing silent runtime failures or undefined behavior.

## 4. Decisions and Assumptions
1. **Zod as Unified Schema Library**: Install `zod` as a direct dependency in both `frontend` (`pnpm --filter ./frontend add zod`) and `backend` (`pnpm --filter ./backend add zod`).
2. **Frontend Validation Layer (`frontend/src/config/env.ts`)**:
   - Create a typed schema validating `VITE_CLERK_PUBLISHABLE_KEY` (required string starting with `pk_`), `VITE_API_URL` (valid URL, default `http://localhost:3000/api`), and `MODE` (`development` | `production` | `test`).
   - Run `safeParse(import.meta.env)` eagerly upon module import.
   - If invalid, format errors using `error.flatten().fieldErrors`, log an explicit readable error to `console.error`, and throw an error to halt execution before invalid API or auth calls occur.
   - Export strongly-typed `env` and `type Env = z.infer<typeof envSchema>`.
   - Update `frontend/src/main.tsx` and `frontend/src/lib/api-client.ts` to consume the typed `env` export.
3. **Backend Validation Layer (`backend/src/config/env.validation.ts`)**:
   - Create a schema validating `PORT` (coerced number, default 3000), `NODE_ENV` (enum, default `development`), `FRONTEND_URL` (valid URL, default `http://localhost:5173`), `CLERK_SECRET_KEY` (required string), `CLERK_PUBLISHABLE_KEY` (optional/default), database credentials (`DATABASE_URL`, `DB_HOST`, `DB_PORT`, `DB_USERNAME`, `DB_PASSWORD`, `DB_NAME`, `DB_SSL`, `DB_LOGGING`).
   - Coerce numeric and boolean types safely (handling string `"true"` / `"false"` correctly).
   - Hook `validateEnv` into `ConfigModule.forRoot({ validate: validateEnv })` in `backend/src/app.module.ts`.
   - Throw a detailed error when validation fails so NestJS aborts bootstrap cleanly with the list of offending variables.
4. **Environment Template Alignment**:
   - Ensure `frontend/.env.example`, `backend/.env.example`, and root `.env.example` contain all required and optional environment keys matching the schemas.

## 6. Requirements
- **Fail-Fast**: Missing required environment variables (e.g. `CLERK_SECRET_KEY` on backend or `VITE_CLERK_PUBLISHABLE_KEY` on frontend) must immediately throw a descriptive error on startup.
- **Type Safety**: Export inferred TypeScript types (`Env`, `EnvironmentVariables`) so all consumers benefit from autocomplete and type checking.
- **Zero Raw Env Drift**: Replace direct unstructured `import.meta.env` access in frontend with the validated `env` singleton.
- **Clean Error Output**: Errors must clearly list which environment variables failed and why (e.g., `"VITE_CLERK_PUBLISHABLE_KEY: [ 'Clerk publishable key must start with \"pk_\"' ]"`).

---

## 7. Security Considerations
- Client-side frontend schema must ONLY include public `VITE_` variables. Never add server secrets (`CLERK_SECRET_KEY`, database passwords) to frontend schemas or `.env` templates.
- Backend schema validates secret keys without echoing sensitive values in logs.

## 10. Exact Manual Test Steps
1. **Frontend Happy Path**: Start frontend with valid root `.env`. App compiles and boots without console errors.
2. **Frontend Fail-Fast Verification**: Temporarily comment out `VITE_CLERK_PUBLISHABLE_KEY` in `.env` and reload frontend. Observe immediate descriptive error banner/console log detailing the exact missing variable.
3. **Backend Happy Path**: Start backend (`pnpm --filter ./backend start:dev`). NestJS bootstraps successfully with all environment variables validated and coerced.
4. **Backend Fail-Fast Verification**: Temporarily invalidate `PORT` (e.g., `PORT=invalid`) or remove `CLERK_SECRET_KEY` and start backend. Observe that NestJS fails to start and outputs the exact validation issues.
