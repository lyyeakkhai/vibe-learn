# Implementation Prompt: 4.6 - Remove Static Mock Data & Wire Frontend to Backend

## 1. Goal
Transition the Vibelearn frontend completely to the live NestJS backend API (`http://localhost:3000/api`). Eliminate the 15,227-line static mock dataset (`src/lib/mock-data.ts`), remove mock fallbacks across `course-service.ts`, `home-page.tsx`, `coursesection.tsx`, `course-detail-page.tsx`, and `learning-page.tsx`, add polished loading skeletons and not-found states, and clean up duplicate CSS files.

---

## 2. Skills Consulted
- `clerk-react-patterns`: Best practices for integrating authentication tokens with backend API client calls.
- `systematic-debugging`: Investigating data flows and ensuring robust error boundaries when switching from static to asynchronous network data.
- `verification-before-completion`: Ensuring strict typechecking, linting, and build verification before asserting task completion.

---

## 3. Code Inspected
- `src/lib/mock-data.ts`: Massive 15,227-line mock file (~675 KB) containing 10 static courses and module trees.
- `src/services/course-service.ts`: Imports `MOCK_COURSES`, uses it as fallback when API calls fail or returns empty, and blends missing API properties with mock data.
- `src/pages/home-page.tsx` & `src/sections/coursesection.tsx`: `<CourseSection />` called without props, defaulting to `MOCK_COURSES.slice(0, 3)` with hardcoded `progress={25}`.
- `src/pages/course-detail-page.tsx`: Initializes state with `initialFallback = MOCK_COURSES.find(...)` and `useState<Course>(initialFallback)`.
- `src/pages/learning-page.tsx`: Initializes state with `initialCourse = MOCK_COURSES.find(...)` and `useState<Course>(initialCourse)`.
- `../vibelearn-backend`: Running live on `http://localhost:3000/api` with endpoints `GET /courses`, `GET /courses/:slug`, `POST /progress`, `PATCH /progress/complete`, `GET /users/me`, `POST /users/sync`.
- `src/globle.css` & `src/index.css`: Redundant, unused CSS duplicate files.

---

## 4. Decisions and Assumptions
1. **Single Source of Truth**: The NestJS backend (`http://localhost:3000/api`) is the sole data provider for courses, modules, lessons, learning outcomes, instructors, and user progress.
2. **Elimination of Mock Dataset**: `src/lib/mock-data.ts` will be completely removed. The app will no longer bundle 675 KB of mock courses.
3. **Home Page Dynamic Loading**: `HomePage` will fetch the courses and user progress using `courseService` and `progressService`, passing them to `CourseSection`.
4. **State Management & Skeletons**:
   - `CourseSection`, `CourseDetailPage`, and `LearningPage` will display semantic Tailwind skeleton loaders matching `DESIGN.md` while awaiting API responses.
   - If a course or lesson does not exist in the database, a friendly "Course Not Found" banner or redirect to `/courses` will be rendered rather than falling back to mock courses.
5. **Service Layer Cleanup**: `courseService` will map backend responses cleanly without merging with mock fallbacks. If the API fails or returns 404, it cleanly returns `null` or `[]` with error logging.
6. **Preservation of Presentational Notes**: The user notes feature on `LearningPage` remains stored locally in the browser's `localStorage` as designed (notes are a client-only scratchpad).
7. **CSS Cleanup**: Remove redundant typo file `src/globle.css` and empty `src/index.css`, retaining `src/globals.css`.

## 6. Requirements
- **No Mock Dependencies**: No frontend file may import from `src/lib/mock-data.ts`.
- **Live Integration**: All course data (catalog, detail syllabus, lesson video and notes, learning outcomes, instructor info) must be fetched from the NestJS backend.
- **Graceful Loading & Error States**: Components must show smooth, accessible skeleton states during network fetches.
- **Strict Theme & Design Tokens**: Adhere to `DESIGN.md` and semantic tokens in `src/globals.css`. No arbitrary hex codes or ad-hoc classes.
- **Type Safety**: Ensure strict TypeScript compliance without `any` regressions.

## 7. Security Considerations

- Maintain client/server boundaries: frontend never attempts direct database access.
