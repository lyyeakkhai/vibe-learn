# Phase 4.8 Implementation Prompt: Role-Based Authorization & View Separation

## 1. Goal
Establish strict role separation between Admin and Normal User roles by adding a `role` column to the PostgreSQL `users` table, securing backend mutation APIs (`courses`, `lessons`, `course-modules`) with a NestJS `RolesGuard`, and gating frontend navigation, routing (`AdminRoute`), and presenting an Access Denied (403) page for unauthorized users.

## 4. Decisions and Assumptions
- **Database Schema:** Add a `role` column (`VARCHAR(20) NOT NULL DEFAULT 'user'`) with a check constraint `CHECK (role IN ('user', 'admin'))` and index to `users` table.
- **Role Assignment:** A user receives the `admin` role if either:
  1. Their Clerk user `publicMetadata.role === 'admin'`.
  2. Their email matches the comma-separated list in the backend `ADMIN_EMAILS` environment variable.
  Otherwise, their role defaults to `'user'`.
- **Backend Protection:** Implement `@Roles('admin')` decorator and `RolesGuard` on NestJS mutation endpoints in `CoursesController`, `LessonsController`, and `CourseModulesController`. Non-admin requests immediately throw `403 Forbidden`.
- **Frontend Navigation:** "Manage Courses" link in both desktop navigation and mobile drawer will strictly render when `isAdmin === true`.
- **Frontend Route Protection:** Wrap `/admin/courses` with `<AdminRoute>`. If a signed-in non-admin accesses `/admin/courses`, render a dedicated 403 `<AccessDeniedPage>` with options to return to courses or home.

## 6. Requirements
- Normal users and visitors cannot see the "Manage Courses" link.
- Normal users navigating to `/admin/courses` are presented with the 403 Access Denied page.
- Direct API calls to mutate courses, modules, or lessons without an admin role return HTTP 403 Forbidden.
- Admins can access `/admin/courses`, see the "Manage Courses" navigation link, and perform full course CRUD.
- All styles strictly use semantic tokens (`bg-primary`, `text-primary-foreground`, `bg-card`, `border-border`, etc.) adhering to `DESIGN.md`.

## 7. Security Considerations
- Defense-in-depth: Both frontend UI and backend API enforce role restrictions.
- Non-admin tokens cannot bypass backend guards even if calling APIs directly via curl or Postman.
- Role resolution is secured on the backend using trusted Clerk token verification and server environment configuration (`ADMIN_EMAILS`).

## 8. Acceptance Criteria
- Running `npm run lint` and `npm run build` passes with zero errors in both `frontend` and `backend`.
- An authenticated user without admin role:
  - Does NOT see "Manage Courses" in navbar or mobile menu.
  - Sees 403 Access Denied page when visiting `/admin/courses`.
  - Receives 403 Forbidden when calling `POST /courses`, `PUT /courses/:id`, or `DELETE /courses/:id`.
- An authenticated admin user:
  - Sees "Manage Courses" in navbar and mobile menu.
  - Can access `/admin/courses` and execute course CRUD.
