## Decisions and Assumptions
1. **Course to Logo Mapping**:
   - `nextjs-app-router-in-depth` -> `frontend/src/assets/courses/nextjs.jpg`
   - `react-performance-engineering` -> `frontend/src/assets/courses/react.jpg`
   - `typescript-for-application-developers` -> `frontend/src/assets/courses/typescript.jpg`
   - `building-ai-apps-with-llms` -> `frontend/src/assets/courses/ai-llms.jpg`
   - `retrieval-augmented-generation-from-scratch` -> `frontend/src/assets/courses/rag.jpg`
   - `python-for-data-work` -> `frontend/src/assets/courses/python.jpg`
   - `system-design-foundations` -> `frontend/src/assets/courses/system-design.jpg`
   - `postgresql-for-developers` -> `frontend/src/assets/courses/postgresql.jpg`
   - `devops-with-docker-and-kubernetes` -> `frontend/src/assets/courses/devops.jpg`
   - `practical-web-security` -> `frontend/src/assets/courses/web-security.jpg`
2. **Automated Upload & Sync Script**:
   - Create a one-off execution script `scripts/upload-course-logos-to-cloudinary.js`.
   - Script will:
     - Read credentials from `.env` using Cloudinary SDK.
     - Upload each image to the `vibelearn/courses` folder with deterministic public IDs (`vibelearn/courses/<course-slug>`).
     - Collect the resulting secure HTTPS Cloudinary URLs (`https://res.cloudinary.com/hgqld91p/image/upload/...`).
     - Connect to the Supabase PostgreSQL database using `pg` and update `public.courses.cover_image_url` for each course by slug.
3. **Database Seed Integrity**:
   - Update `supabase/seed.sql` and `backend/docs/seed.ndjson` with the newly generated Cloudinary URLs so database re-seeds or fresh setups do not revert to `picsum.photos`.
4. **Security & Performance**:
   - Cloudinary API secrets remain server-side.
   - Frontend receives optimized, CDN-backed Cloudinary URLs via the existing `courseService` and API endpoints.
